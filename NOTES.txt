2. AURA AR CAMPUS NAVIGATION (CAPSTONE)
============================================================

What
Phone AR app. Places a SketchUp model of the school in the room, then walks the user to a room with a minimap, arrows, and search. Product name: Aura. Scene that matters: finalapp 2.

Path
D:\capstone
User manual: Docs\users-manual.md
Change log: STATUS.md
Contributor on the manual: Cyrus Wendell P. De Sosa

Stack
- Unity 6000.3.11f1, URP, AR Foundation, ARCore on Android
- Input System only. Do not call legacy UnityEngine.Input
- Pre-placed nodes under Building_Floorplan. A* in FinalUserNavigationController
- ML under Tools\ml_pipeline and v2m_video_pipeline. Label Studio was used. Keep yolo_hybrid, dataset_seg_hybrid, the latest YOLO run, and segformer
- Unity MCP package: com.ivanmurzak.unity.mcp
- Android APKs were built from this folder

Flow that was built
Welcome, then "at the entrance" or "already inside", then floor choice, then a bird's-eye map tap, then Start / Confirm. That drops an ARAnchor named WorldAnchor. Building_Floorplan stays parented to that anchor so the map does not ride the camera.

Walking on the phone uses the AR camera delta times androidLocomotionMetersScale, with a jump clamp and smoothing. GPS hybrid was tried and turned down. Indoor GPS is noisy. A small "Walk x" tuner saves to PlayerPrefs.

Mesh1 and Mesh2 are the floors. Height decides which floor the minimap treats as current. Renderers stay on so pathfinding colliders do not vanish. Search is a maps-style box over waypoint nodes (WaypointSearchAndNavigateUI). Arrows and the route line follow the obstacle-lifted path. They must not cut through walls. Arrival clears the path and can speak with Android TTS.

QR image anchoring was removed. Anchoring is manual Start / Confirm only.

FinalAppPresentationCheat forces a desktop demo and can tint the floorplan magenta. Minimap and arrows stay their own colors.

Defense docs
Docs\system-block-diagram.svg
Docs\system-schematic-diagram.svg
Docs\system-flow-chart.svg
plus a PNG of the flow chart
Docs\users-manual.md

Do not rename
finalapp 2, Building_Floorplan, Mesh1, Mesh2, Nodes, Player, Player 2 (inactive pose marker), AR_XRHost, NavigationSystems, ViewCamera, FinalApp_UICanvas, WorldAnchor.
GameObject.Find fallbacks use these names.

Scripts
- Assets\Scripts\FinalAppSimple\FinalAppARFloorplanAnchor.cs
- Assets\Scripts\FinalAppSimple\FinalAppCircularMinimap.cs
- Assets\Scripts\FinalAppSimple\AuraOnboardingFlow.cs
- Assets\Scripts\FinalAppSimple\FinalAppPresentationCheat.cs

- Assets\Scripts\ARCampusNavigationDev\NodeInteractionController.cs

Scale
Building_Floorplan localScale is 280. That is the SketchUp authoring scale, not measured meters. Do not rescale the building to fix walking. Tune androidLocomotionMetersScale.

How he works on it
He sends Game view or phone photos when the map is pink, arrows are wrong, the player falls, or search is empty. Read the shot, then the script and the scene. Append real changes to STATUS.md. Refresh and compile before calling it build-ready.
Editor Play Mode is a desktop stand-in. AR subsystems are off in the Editor on purpose. Device truth is an Android build.

Bugs that already ate time
- Floorplan looked solid on device when the material was not really transparent (URP Unlit, _Mode, _TintColor).
- Map drifted because Building_Floorplan got parented under the camera or player, or the anchor froze while tracking kept moving.
- A* found no path when the graph had no edges, when physics chords were skipped, or when the safety plane was in the raycast mask.
- Android search text snapped back to the partial query because the soft keyboard restored it.
- Minimap proxies copied the cyan floor tint and looked like a slab.
- Player 2 must stay a transform marker. A second CharacterController phased through the mesh.
- C: fills up from Unity temp, Gradle, and ML frame dumps. Clean generated caches, not the source model or the current dataset.
